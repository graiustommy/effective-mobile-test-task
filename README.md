# API управления подписками

Это REST API для управления подписками пользователей с возможностью фильтрации по диапазону дат и агрегирования данных.

## Предварительные требования

На вашей системе должны быть установлены Docker и Docker Compose. Проект запускает три сервиса: базу данных PostgreSQL, приложение Go API и интерфейс документации Swagger UI.

## Настройка

Перед запуском проекта создайте файл .env в корневом каталоге проекта со следующей конфигурацией. При необходимости замените значения на свои:

```
db_user=user
db_password=password
db_name=subscriptions
db_port=5432
```

## Запуск проекта

Запустите все сервисы следующей командой из корневого каталога проекта:

```bash
docker-compose up -d
```

Это запустит базу данных PostgreSQL, сервер API на порту 8080 и интерфейс Swagger UI на порту 8081. Сервисы могут потребовать некоторое время для запуска, особенно при инициализации базы данных и выполнении миграций.

## Доступ к API

После запуска сервисов вы можете получить доступ к документации API и выполнять запросы. Откройте веб-браузер и перейдите на http://localhost:8081 для просмотра полной документации API в формате Swagger UI. Этот интерфейс показывает все доступные конечные точки с примерами и позволяет тестировать запросы прямо из браузера.

Вы также можете отправлять прямые HTTP запросы к API на адресе http://localhost:8080. Например, для создания подписки отправьте POST запрос на http://localhost:8080/create/ с соответствующей JSON полезной нагрузкой.

## Остановка проекта

Для остановки всех запущенных сервисов выполните следующую команду:

```bash
docker-compose down
```

Это остановит и удалит контейнеры, сохраняя ваши данные. Для полной очистки и удаления всех данных добавьте флаг -v:

```bash
docker-compose down -v
```

## Конечные точки API

API предоставляет конечные точки для создания, чтения, обновления и удаления подписок. Он также поддерживает операции агрегирования, такие как подсчёт подписок по идентификатору пользователя или названию сервиса. Подробную информацию о форматах запросов и ответов, правилах валидации и обработке ошибок смотрите в документации Swagger UI.
